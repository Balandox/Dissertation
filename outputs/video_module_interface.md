# Интерфейс видеомодуля → fuzzy / ML

Документ описывает формат данных, которые видеомодуль передаёт на вход
модулям слияния (fuzzy-логика и ML-классификатор). Это контракт между
модулями — при чтении этого файла ты должен полностью понимать, что
представляют собой входные признаки, как они получены и каких значений
от них ожидать.

---

## 1. Откуда берутся данные

Видеомодуль обрабатывает видеозаписи из датасета **UTA-RLDD**
(University of Texas at Arlington Real-Life Drowsiness Dataset):
- 60 участников, 180 видеозаписей (~10 минут каждое)
- 3 класса: `alert` (бодрый), `low vigilant` (предусталость), `drowsy` (сонливый)
- Реальная сонливость (не симулированная)
- Записано на личные камеры/телефоны → разное разрешение, ориентация, FPS

Пайплайн обработки:
```
Видеокадр → MediaPipe Face Mesh (478 точек)
         → EAR (Eye Aspect Ratio), MAR (Mouth Aspect Ratio) покадрово
         → Детектор морганий (FSM на основе EAR)
         → Детектор зеваний (на основе MAR)
         → Агрегация по скользящему окну (60 сек, шаг 10 сек)
         → 6-мерный вектор признаков + метка класса
```

---

## 2. Формат выходных данных

Видеомодуль сохраняет результаты в файл **`outputs/video_features.csv`**.

### Колонки

| Колонка | Тип | Описание |
|---|---|---|
| `subject_id` | int | ID участника (1–60) |
| `fold` | int | Номер фолда (1–5), для кросс-валидации |
| `class_id` | int | Метка класса: 0, 1 или 2 |
| `class_name` | str | `"normal"`, `"pre_fatigue"` или `"drowsy"` |
| `video_filename` | str | Имя исходного видеофайла |
| `window_start_ms` | int | Начало временного окна (мс от начала видео) |
| `window_end_ms` | int | Конец временного окна (мс от начала видео) |
| **`avg_ear`** | float | Среднее EAR за окно |
| **`blink_rate`** | float | Морганий в минуту |
| **`avg_blink_duration`** | float | Средняя длительность моргания (мс) |
| **`prolonged_blink_count`** | int | Количество длинных морганий (>500 мс) в окне |
| **`perclos`** | float | Доля времени с закрытыми глазами [0, 1] |
| **`yawn_count`** | int | Количество зеваний в окне 5 минут |

**Жирным** выделены 6 признаков, которые подаются на вход fuzzy/ML модели.
Остальные колонки — метаданные (метка класса, ID участника и т.д.).

### Структура строк
Одна строка CSV = одно временное окно. Для одного 10-минутного видео
получается ~55 строк (окно 60 сек со сдвигом 10 сек).
Все строки от одного видео имеют одинаковые `subject_id`, `class_id`, `class_name`.

## 3. Маппинг классов

| class_id | class_name | Оригинал UTA-RLDD | Описание |
|---|---|---|---|
| 0 | `normal` | alert (0) | Бодрый, нормальное состояние |
| 1 | `pre_fatigue` | low vigilant (5) | Предусталость, ранние признаки |
| 2 | `drowsy` | drowsy (10) | Сонливый, выраженная усталость |

---

## 4. Описание каждого признака

### 4.1. avg_EAR — среднее Eye Aspect Ratio

**Что это:** соотношение вертикальных и горизонтальных расстояний между
веками, усреднённое по всем кадрам окна (где найдено лицо).

**Формула EAR для одного кадра:**
```
EAR = (||p2 - p6|| + ||p3 - p5||) / (2 * ||p1 - p4||)
```
где p1–p6 — 6 ключевых точек глаза. EAR считается отдельно для левого
и правого глаза, затем усредняется.

**Физический смысл:** при открытых глазах EAR ≈ 0.25–0.35,
при закрытых EAR < 0.20, при моргании резкий провал к ~0.10.

**Ожидаемые значения:**
- `normal`: 0.26 – 0.33 (среднее ~0.29)
- `pre_fatigue`: 0.24 – 0.32 (среднее ~0.28)
- `drowsy`: 0.20 – 0.32 (среднее ~0.27)

**Тренд:** при усталости снижается — глаза чаще полуприкрыты.

---

### 4.2. blink_rate — частота морганий (в минуту)

**Что это:** количество морганий в окне, пересчитанное на минуту.

**Как детектируется моргание:** конечный автомат на временном ряду EAR.
Переход OPEN → CLOSED происходит, когда EAR падает ниже порога 0.21
в течение ≥2 кадров подряд. Переход CLOSED → OPEN — когда EAR
возвращается выше порога. Одно моргание = один полный цикл.

**Физический смысл:** у бодрого человека 10–20 морганий в минуту.
При усталости частота повышается (особенно характерны нерегулярные
пачки морганий).

**Ожидаемые значения:**
- `normal`: 4 – 20 (среднее ~10.6)
- `pre_fatigue`: 8 – 26 (среднее ~16.1)
- `drowsy`: 7 – 37 (среднее ~16.3)

**Тренд:** при усталости повышается, но неравномерно — у некоторых
участников в состоянии drowsy частота падает (микросны).

---

### 4.3. avg_blink_duration — средняя длительность моргания (мс)

**Что это:** среднее время (в миллисекундах) между началом
и концом каждого моргания в окне.

**Физический смысл:** нормальное моргание длится ~100–200 мс.
Длинные моргания (>400 мс) — признак микросна или глубокой усталости.

**Ожидаемые значения:**
- `normal`: 100 – 400 мс (среднее ~184)
- `pre_fatigue`: 120 – 350 мс (среднее ~220)
- `drowsy`: 90 – 1200 мс (среднее ~346)

**Тренд:** при усталости сильно возрастает — это один из самых
дискриминативных признаков. В состоянии drowsy может достигать 1000+ мс.

---

### 4.4. prolonged_blink_count — количество длинных морганий

**Что это:** количество морганий длительностью > 500 мс в окне 60 сек.

**Физический смысл:** длинные моргания — прямой индикатор микросна.
У бодрого человека их 0–1 за минуту, у сонного может быть 5–15.

**Ожидаемые значения:**
- `normal`: 0 – 2 за окно
- `pre_fatigue`: 0 – 2 за окно
- `drowsy`: 0 – 15 за окно

**Тренд:** сильно растёт при выраженной сонливости — наиболее
специфичный признак для класса drowsy.

---

### 4.5. perclos — доля времени с закрытыми глазами

**Что это:** PERCLOS = (кадры с EAR < 0.21) / (всего кадров с лицом) в окне.
Значение в диапазоне [0, 1].

**Физический смысл:** один из наиболее устоявшихся индикаторов
сонливости в литературе (стандарт NHTSA). При нормальном бодрствовании
PERCLOS < 0.08, при выраженной сонливости > 0.15.

**Ожидаемые значения:**
- `normal`: 0.01 – 0.07 (среднее ~0.031)
- `pre_fatigue`: 0.03 – 0.09 (среднее ~0.057)
- `drowsy`: 0.02 – 0.59 (среднее ~0.12)

**Тренд:** монотонно растёт при нарастании усталости. Важно: высокая
вариативность в классе drowsy — некоторые участники в этом состоянии
почти спят (PERCLOS ~0.5), другие держатся (PERCLOS ~0.05).

---

### 4.6. yawn_count — количество зеваний

**Что это:** число зеваний в окне **5 минут** (в отличие от других
признаков, у этого расширенное временное окно — зевания редки).

**Как детектируется зевание:** MAR (Mouth Aspect Ratio) > 0.6
в течение > 1.5 секунд. Это отфильтровывает разговор, улыбку, короткие
открытия рта.

**Ожидаемые значения:**
- `normal`: обычно 0
- `pre_fatigue`: 0 – 2
- `drowsy`: 0 – 5

**Важное замечание:** признак разреженный — во многих окнах может быть 0,
даже в классе drowsy. Использовать с осторожностью: сильный позитивный
сигнал, когда > 0, но отсутствие зеваний ничего не означает.

## 5. Рекомендации по использованию

### 5.1. Предобработка перед обучением

1. **Нормализация:** признаки имеют разные масштабы (EAR ≈ 0.2–0.3,
   blink_duration в мс, PERCLOS в [0,1]). Для fuzzy это ОК (каждая
   переменная настраивается отдельно), для ML — применить StandardScaler
   или MinMaxScaler.

2. **yawn_count разреженный:** возможно, имеет смысл преобразовать
   в бинарный признак (`has_yawn` = yawn_count > 0) или оставить как есть.

3. **Межсубъектная вариативность:** значения сильно зависят от человека
   (у одних базовый EAR = 0.27, у других = 0.33). При разбиении на
   train/test **нельзя смешивать одного участника в обе выборки** —
   это приведёт к утечке данных. Используй разбиение по `subject_id`
   или по `fold` (поле уже есть в CSV).

### 5.2. Разбиение на train/test

Правильный подход — **subject-independent split**:
```python
# Вариант 1: leave-one-fold-out (по полю fold)
test = df[df["fold"] == 1]
train = df[df["fold"] != 1]

# Вариант 2: leave-one-subject-out
from sklearn.model_selection import GroupKFold
gkf = GroupKFold(n_splits=5)
for train_idx, test_idx in gkf.split(X, y, groups=df["subject_id"]):
    ...
```

### 5.3. Целевая переменная

Для классификации — `class_id` (0, 1, 2) или `class_name`.
Задача — многоклассовая классификация на 3 класса.
Классы приблизительно сбалансированы (по 30–33% окон на класс).

### 5.4. Признаки для подачи в модель

```python
FEATURE_COLS = [
    "avg_ear",
    "blink_rate",
    "avg_blink_duration",
    "prolonged_blink_count",
    "perclos",
    "yawn_count",
]
X = df[FEATURE_COLS].values
y = df["class_id"].values
```

## 6. Ограничения и нюансы

1. **Признак yawn_count не информативен на коротких сегментах.**
   Зевания редки, и в большинстве окон 60 сек их нет. Если при обучении
   этот признак окажется не значимым (низкий feature importance) — это
   ожидаемо, не баг.

2. **Разные участники по-разному проявляют усталость.** У некоторых
   в состоянии drowsy метрики почти не меняются — они держатся усилием
   воли. Это реальная сложность задачи, не проблема датасета.

3. **Признаки коррелированы.** avg_EAR, PERCLOS и avg_blink_duration
   связаны (все через EAR). ML-модели с деревьями (RF, XGBoost) с этим
   справляются, линейным моделям может мешать мультиколлинеарность.

4. **Окна перекрываются** (60 сек окно со сдвигом 10 сек). Соседние
   строки внутри одного видео сильно коррелированы. Это нужно учитывать
   при оценке точности — метрики могут быть оптимистично завышены, если
   не делать разбиение по субъектам.

5. **Метки self-reported.** В UTA-RLDD участники сами оценивали своё
   состояние перед записью. Шум в метках неизбежен, особенно между
   `normal` и `pre_fatigue`.
